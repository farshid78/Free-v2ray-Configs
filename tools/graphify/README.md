# graph.html overlay

`graphify-out/graph.html` is generated by graphify's `export.to_html`. Its
search box only fills a dropdown (the canvas never changes) and its community
legend click handler can never solo a community.

The fix lives here, not in graphify:

- `ui.css`, `ui.js` — the overlay: dim non-matching nodes, count the hits, keep
  the query when a result is picked, and give the legend single click
  (hide/show) plus double click (solo).
- `build.py` — renders the page with the **unmodified** graphify install and
  injects the overlay before `</body>`, then verifies that the embedded
  `RAW_NODES` / `RAW_EDGES` / `LEGEND` arrays match the graph it rendered.

Because the package is never edited, reinstalling or re-cloning graphify cannot
revert the behaviour — rebuild the page and the fix is back.

```powershell
python -X utf8 tools/graphify/build.py
```

The builder continues inside `.cache/gv` and recreates that virtualenv (pinned
`graphifyy==0.1.14`) when it is missing. The page is drawn from
`graphify-out/graph.json`, the artifact `GRAPH_REPORT.md` and `obsidian/` also
describe, so a cache wipe or a graphify upgrade cannot change the counts it
shows; community labels live in the repo at
`graphify-out/community-labels.json` and are mirrored from graphify's cache when
that file is absent.

Use `--no-venv` to render with an interpreter that already imports graphify, and
`--out PATH` to write somewhere other than `graphify-out/graph.html`.
